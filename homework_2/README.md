# NewsFlow — персональная RSS-лента

Нужен Python 3.11 или 3.12. Из корня репозитория:

```bash
cd homework_2
./run.sh --demo --open
```

При первом запуске скрипт создаст `venv`, установит зависимости и загрузит модель.
После запуска откроется **http://127.0.0.1:8000/** с готовыми профилями, фильтрами
и учебными новостями. Демонстрационные данные хранятся отдельно в `data/demo.db`.
В режиме `--demo` эта база используется даже при заданном `RSS_DB_PATH`, чтобы не
добавлять примеры в личные данные.

Для личного использования запустите `./run.sh --open`, создайте профиль, фильтр и
подписку либо собственный канал. По умолчанию личная БД — `data/news.db`.
Пока фильтров нет, персональная лента пустая. API доступен по `/docs`.

Повторный запуск использует готовое окружение и проверяет модель из локального кэша.
Он не обновляет pip и не устанавливает пакеты, если зависимости подходят.

```bash
./run.sh --setup       # установить зависимости / подготовить модель и запустить
./run.sh --offline     # готовое окружение и модель, без установки пакетов и загрузки модели
./run.sh --demo --offline --open  # демонстрация с подготовленным окружением и кэшем
./run.sh --reload      # разработка с перезапуском при изменении кода
PORT=8001 ./run.sh --demo --open  # другой локальный порт
```

Для внешних RSS всё ещё нужен интернет; собственный канал и фильтры работают локально.
Остановка сервера — `Ctrl+C` в терминале запуска.

Скрипт сохраняет существующее окружение. Для другого укажите отдельный каталог:

```bash
PYTHON=python3.12 VENV_DIR=venv312 ./run.sh --setup
```

`requirements.txt` — единый источник зависимостей. Метаданные `pyproject.toml` читают
его же. Проверенные версии семантических библиотек указаны в этом файле.
Если окружение создано вручную, можно установить пакеты через
`venv/bin/python -m pip install -r requirements.txt`.

## Данные и модель

`RSS_DB_PATH` и `HF_HOME` позволяют выбрать постоянные пути к личной базе и кэшу
Hugging Face. При смене `HF_HOME` сначала выполните `./run.sh --setup`, а перед
автономной демонстрацией — `./run.sh --offline`. Используйте те же пути и пользователя
ОС при подготовке и показе. Если кэш отсутствует, обычный запуск скачает модель;
`--offline` завершится с понятным сообщением о необходимой подготовке.

## Проверки

```bash
venv/bin/python -m pip install -e '.[test,browser]'
venv/bin/python -m playwright install chromium
venv/bin/python -m pytest -q
venv/bin/python -m pytest -q tests/test_browser_ui.py
HF_HUB_OFFLINE=1 RUN_MODEL_TESTS=1 venv/bin/python -m pytest -q
```

Тесты с `RUN_MODEL_TESTS=1` требуют заранее подготовленную модель. Остальные тесты
движков используют подставной encoder и не загружают веса. Браузерные тесты пропускаются,
если Playwright или Chromium не установлены. Для уже установленного Chromium можно
передать путь к исполняемому файлу в `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

## Docker

Из `homework_2` соберите образ, затем подготовьте модель в постоянном volume:

```bash
docker build -t newsflow .
docker volume create newsflow-data
docker volume create newsflow-models
docker run --rm -v newsflow-models:/srv/models/hf-cache newsflow \
  python -m scripts.prepare_semantic
docker run --rm -p 8000:8000 \
  -v newsflow-data:/srv/data -v newsflow-models:/srv/models/hf-cache newsflow
```

Откройте http://127.0.0.1:8000/. Образ использует CPU-сборку PyTorch и проверяет
подготовленный локальный кэш перед запуском сервера. Volume с БД сохраняет пользователей,
подписки, фильтры и публикации после перезапуска. Volume модели должен быть тем же при
подготовке и запуске; кэш с ноутбука автоматически в контейнер не переносится.
