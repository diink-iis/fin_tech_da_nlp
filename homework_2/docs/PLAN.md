# Проект №2: агрегатор новостей из RSS. План и разбиение на 5 человек

Цель — оценка 10. Ступени накапливаются, поэтому строим по этапам: сначала работает ядро на 6, затем семантика (8), затем многопользовательский режим (10).
Условие — в [../TASK.md](../TASK.md). Все решения ниже — предложение для обсуждения командой, не готовый факт.

## 1. Что должно работать на приёмке

| Шаг приёмки | Что это значит для приложения |
|-------------|-------------------------------|
| Показ фильтров и ленты | в ленте только новости, прошедшие фильтры; у каждой видно, какой фильтр сработал и почему |
| Пост в свой RSS-канал | из интерфейса создаётся статья, канал отдаётся как настоящий RSS по HTTP, статья появляется в ленте |
| Добавление фильтров через интерфейс | без перезапуска, лента пересчитывается |
| Новый канал по ссылке преподавателя, **перезапуск сервиса** | каналы, пользователи и фильтры хранятся в БД и переживают перезапуск; новые новости появляются сразу после добавления канала |
| 10 баллов: случайный человек из аудитории | создаёт пользователя, подписки и фильтры сам, без инструкции |

## 2. Архитектура

```
RSS-ленты (внешние + свой канал)
        │  HTTP, раз в N минут и по кнопке «обновить»
        ▼
  Агрегатор ──► SQLite ◄── REST API (FastAPI) ◄── Веб-интерфейс (SSE для онлайна)
   (fetcher,       ▲                │
    дедупликация)  │                ▼
                   └────── Движки фильтрации
                          ├─ ключевые слова (леммы, AND/OR/NOT, фразы)
                          └─ семантика (эмбеддинги, порог сходства)
```

Предлагаемый стек (согласовать): Python 3.12, FastAPI, SQLite, `feedparser` + `httpx` для чтения лент, `pymorphy3` для лемм (уже использовали в задании №1),
`sentence-transformers` с лёгкой русской моделью (например `cointegrated/rubert-tiny2`, ~110 МБ, работает на CPU) для семантики,
фронтенд на Jinja + немного JS (без сборки), онлайн-обновление через SSE. Без облачных API: приёмка идёт на ноутбуке, возможно без интернета.
Свой RSS-канал отдаётся тем же приложением по адресу `/rss/{id}.xml`, поэтому читается так же, как внешний.

Ключевая идея: **новости хранятся один раз на всех** (по ленте), а **фильтры и подписки у каждого пользователя свои**. Лента пользователя — это новости его
каналов, прошедшие хотя бы один его фильтр; результат совпадения сохраняется вместе с причиной.

## 3. Контракты между модулями

Фиксируются в `app/contracts.py` в первый день; дальше меняются только по согласию всех пятерых, отдельным PR (как в задании №1).

```python
@dataclass
class Article:            # новость в хранилище
    id: int; feed_id: int; guid: str
    title: str; summary: str; link: str; published_at: datetime

@dataclass
class Filter:             # фильтр пользователя
    id: int; user_id: int; name: str
    kind: Literal["keyword", "topic"]
    params: dict          # keyword: {"any": [...], "all": [...], "none": [...], "fields": ["title","summary"]}
                          # topic:   {"description": "...", "threshold": 0.45}

@dataclass
class MatchReason:        # почему новость в выдаче — показывается в интерфейсе
    filter_id: int; filter_name: str; kind: str
    details: dict         # keyword: {"matched": ["нефть"], "in": "title"}
                          # topic:   {"score": 0.62, "threshold": 0.45}

class FilterEngine(Protocol):
    def match(self, article: Article, flt: Filter) -> MatchReason | None: ...
```

Функции, на которых стыкуются модули:

| Функция | Модуль | Выход |
|---------|--------|-------|
| `KeywordEngine.match(article, flt)` | ядро фильтрации | `MatchReason` или `None` |
| `SemanticEngine.match(article, flt)`, `SemanticEngine.index(articles)` | семантика | то же; вектор статьи считается один раз при загрузке |
| `fetch_feed(url) -> list[Article]` | агрегатор | новые статьи ленты, без дублей |
| `create_channel`, `post_article`, `render_rss(channel_id) -> str` | свой канал | валидный RSS 2.0 |
| `repository`: пользователи, ленты, подписки, фильтры, статьи, совпадения | бэкенд | синхронные функции над SQLite |

REST API (черновик, уточняет роль 4):

| Метод и путь | Назначение |
|--------------|------------|
| `POST /api/users`, `GET /api/users` | создать и перечислить пользователей |
| `GET/POST/DELETE /api/users/{u}/feeds` | подписки пользователя, добавление канала по ссылке |
| `GET/POST/PUT/DELETE /api/users/{u}/filters` | фильтры пользователя |
| `GET /api/users/{u}/news` | лента: статьи с причинами совпадения |
| `GET /api/users/{u}/stream` | SSE: новые статьи онлайн |
| `POST /api/channels`, `POST /api/channels/{c}/articles`, `GET /rss/{c}.xml` | свой канал: создать, запостить статью, отдать RSS |
| `POST /api/refresh` | принудительно обновить ленты |

## 4. Роли

| # | Роль | Файлы | Что делает | Готово, когда |
|---|------|-------|------------|---------------|
| 1 | Фильтрация по ключевым словам | `app/engines/keyword.py` | нормализация и леммы, `any/all/none`, фразы, поля заголовок/текст, подсветка и список совпавших слов для объяснения | табличные тесты `match` проходят, без зависимости от остальных модулей |
| 2 | Семантический поиск | `app/engines/semantic.py` | выбор и загрузка локальной модели, эмбеддинги статей и описаний тем, косинусное сходство, порог, кэш векторов, оценка в объяснении | тема «политика» находит статьи без слова «политика», время обработки укладывается в бюджет на ноутбуке |
| 3 | Агрегатор и свой канал | `app/aggregator.py`, `app/channels.py` | чтение лент (кодировки, даты, дубли по guid), периодический опрос, обновление по кнопке, свой канал: создание, постинг, генерация RSS 2.0 | канал отдаёт валидный RSS, чужой канал читается так же, как свой |
| 4 | Бэкенд, данные, пользователи, интеграция | `app/main.py`, `app/db.py`, `app/contracts.py`, `Dockerfile`, CI | схема БД, пользователи, подписки, фильтры, REST и SSE, связывание движков, сохранение при перезапуске, Docker и CI, README | сервис перезапускается без потери данных, весь API работает на заглушках движков с первого дня |
| 5 | Интерфейс, тесты, презентация | `app/static`, `app/templates`, `tests/` | лента с бейджами фильтров и причин, редактор фильтров, пользователи и подписки, форма поста в свой канал, онлайн-обновление; сквозные тесты и сценарий приёмки; слайды про архитектуру и движки | сценарий приёмки из раздела 1 проходит вручную по скрипту без подсказок |

Роли 1 и 2 не знают о БД и сети: движки получают `Article` и `Filter`. Роль 4 собирает всё в одном месте; другие модули друг друга не импортируют.

## 5. Порядок работы

1. **День 1.** Роль 4 готовит каркас: `contracts.py`, `db.py` со схемой, API с заглушками движков и `Dockerfile`. Роли 1–3 пишут свои модули на простых строках, роль 5 верстает интерфейс на заглушечных данных и описывает сценарий приёмки.
2. **Этап «6»:** ключевые слова, чтение лент, свой канал, интерфейс фильтров и ленты, каналы и фильтры в БД. Проверка: весь шаг приёмки со своим каналом.
3. **Этап «8»:** семантические фильтры в тех же формах, объяснение со сходством и порогом. Проверка: тема без совпадения слов находит нужные новости.
4. **Этап «10»:** пользователи, свои подписки и фильтры у каждого. Проверка: «случайный человек» проходит настройку сам.
5. **Финал.** Слайды, репетиция демонстрации с перезапуском сервиса и чужим каналом, проверка на ноутбуке без интернета.

## 6. Риски и решения

| Риск | Что делаем |
|------|-----------|
| Нет интернета на приёмке | модель эмбеддингов лежит в репозитории или скачивается заранее; свой канал работает локально; для чужой ссылки интернет всё равно нужен |
| Размер и скорость модели | лёгкая модель, векторы считаются один раз при загрузке статьи, на старте ничего не пересчитывается |
| Потеря данных при перезапуске | всё хранится в SQLite; каналы, фильтры и пользователи проверяются тестом с перезапуском |
| Битые и нестандартные RSS (Atom, кодировки, даты без часового пояса) | парсинг через `feedparser`, тесты на реальных лентах разных изданий |
| Дубли новостей | уникальность по паре «лента, guid», запасной вариант — ссылка |
| Непонятный интерфейс для «случайного человека» | подсказки в пустых состояниях, готовые примеры фильтров, проверка на человеке вне команды |
| Семантика даёт случайные совпадения | порог настраивается в интерфейсе, оценка сходства показана в объяснении |
